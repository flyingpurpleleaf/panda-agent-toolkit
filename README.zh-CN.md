# panda-agent-toolkit

[English](./README.md) | **中文**

panda-agent-toolkit 是一个结构化、工程化导向的 Agent 工具集仓库，源自十年一线软件开发经验的沉淀。

它旨在集中维护以下内容：

- 可复用的 Skill：既包括我自研的，也包括日常开发中实际使用的
- 为一致性与可重复性而设计的 Prompt 模板
- MCP 配置与集成模式
- 用于约束 Agent 行为、保证可预期性的 Rules
- 来自真实使用场景的经验记录与最佳实践

它不是一个零散片段的集合，而是把 Agent 工具链当作严肃工程流程的一部分来对待。

---

## 为什么要有这个仓库

Agent 开发这件事，起步容易，保持整洁很难。

多数人最终会变成这样：

- Prompt 片段散落在笔记和聊天记录里
- Skill 用完一次就再也没有复用
- MCP 配置靠复制粘贴，过期且无人维护
- Agent Rules 只存在于某个人的脑子里
- 踩过的坑从来没被记录下来

这个仓库就是为了解决这些问题。

它不是框架，也不是产品。它是一个真正在用的工具箱——有结构、有版本、可复用。

## 仓库内容

### 1. Skills

面向 Agent 与日常开发的可复用能力。

```
skills/
├── custom/          # 我自研的 Skill
├── daily/           # 日常开发中实际使用的 Skill
└── shared/          # 通用工具与辅助能力
```

每个 Skill 都会记录：

- 用途
- 输入 / 输出
- 使用示例
- 已知限制

---

### 2. Prompt 模板

为一致性与可重复性而设计的模板。

```
prompts/
├── coding/          # 代码生成、评审、重构
├── writing/         # 文档、总结、报告
├── analysis/        # 调研、对比、决策
└── workflow/        # 多步骤与 Agent 工作流
```

设计原则：

- 优先保证结构清晰，而不是措辞取巧
- 模板参数化，便于复用
- 行为发生变化时，对模板进行版本管理

---

### 3. MCP 集成

Model Context Protocol 的配置与集成模式。

```
mcp/
├── configs/         # 服务端与客户端配置
├── patterns/        # 常见集成模式
└── notes/           # 注意事项、限制、调试技巧
```

关注点：

- 可靠的本地开发环境配置
- 配置与密钥的清晰分离
- 明确记录失败模式

---

### 4. Agent Rules

用于约束 Agent 行为、保证可预期性的规则。

```
rules/
├── global/          # 全局常驻行为准则
├── project/         # 项目级约束
└── safety/          # 安全边界与防护
```

目标：

- 让 Agent 行为显式化，而非隐式约定
- 减少跨会话的意外与漂移
- 规则保持小而可测、可评审

---

### 5. 文档

来自真实使用场景的实践记录与经验总结。

```
docs/
├── guides/          # 分步指南
├── lessons/         # 复盘与踩坑记录
├── comparisons/     # 工具与方法对比
└── reference/       # 速查表与快速参考
```

这一部分是刻意带有主观判断的。它记录的是：什么真正有效、什么失败了、以及为什么。

---

## 设计原则

1. **结构优先于堆积** —— 一套小而有序的内容，胜过一堆大而混乱的内容。
2. **复用优先于重复** —— 一个东西用到第二次，就应该被沉淀到这里。
3. **显式优先于隐式** —— Rules、Prompt、配置都应当是可读的。
4. **文档是工具的一部分** —— 没有文档的 Skill，就是未完成的 Skill。
5. **工程纪律同样适用于 Agent** —— 把 Agent 工具链当作生产代码来对待。
